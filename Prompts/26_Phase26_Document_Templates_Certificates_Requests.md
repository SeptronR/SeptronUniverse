# PHASE 26 — DOCUMENT TEMPLATES, CERTIFICATES & REQUESTS

## Pre-Requisite
Phases 01–12 complete (file service with signed URLs, background jobs, number sequences, workflow engine with `certificates.request`, fee linkage, students/staff/alumni identities). Earlier phases (07 ID cards/undertakings, 08 offers, 14 hall tickets, 15 grade cards, 16 transcripts, 18 degrees/provisional, 20 allotment letters, 25 event certificates) rendered with **platform default templates** and stored `pdf_url` on their own rows; this phase delivers the real builder/renderer, the issued-document register, and back-fills those rows.

## Objective
One document engine for every certificate and letter in the institution: a **template builder** (block layout JSONB + HTML/CSS, variables catalogue per template type, institution/pack defaults with per-institution overrides, versioning, **bilingual** layouts), a **renderer** (Jinja2 → WeasyPrint, fonts for Indian scripts, QR/barcode, signatures/seals, watermarks), an **issued-document register** (`document_number` from sequences, **serial registers** for statutory books, `content_hash`, `verification_token`, revoke/reissue), **time-limited signed download links** with per-download watermarks, **bulk generation jobs** (ID cards, bonafide for a batch, course-completion, experience letters), **self-service certificate requests** by students/staff/alumni with fees, approval workflow, generation, issue and delivery (digital/pickup/post), the **unified public verification endpoint**, and a hook API (`documents.render(template_type, entity, variables)`) that every other phase now calls — with self (my documents/requests) vs registrar/office (all) views.

## Feature keys
`documents.templates`, `documents.bulk_generation` (on, starter); `documents.certificate_requests` (on, standard; depends `workflow.engine`, `fees.core`); `documents.serial_registers`, `documents.watermark_signed_links` (on, standard); `documents.bilingual_templates` (off, standard).

## 26.6 Services
- `template_service.py` (`documents.templates`, `documents.bilingual_templates`)
  1. Templates per `template_type`: platform default (pack) → institution override (clone → edit → preview → publish new `version`; older versions kept for re-render fidelity); `layout` blocks (header/logo, title, body paragraphs with variables, tables, photo, QR/barcode, signatures, seal, footer, watermark) compiled to `html_template` by the builder, or raw HTML/CSS for advanced users; `variables` catalogue per type resolved from entity sources (student, enrolment, programme, term results, staff, event, hostel, institution profile, signatories) with examples; sandboxed Jinja (no attribute access to ORM beyond the catalogue).
  2. Bilingual: secondary language blocks rendered side by side/below with fonts (Noto Devanagari/Tamil/Telugu/… bundled) and transliteration helpers for names when available (`students.name_secondary` when captured, else same script); language selection at render.
  3. Preview with sample entity or manual variables → PDF/PNG (no register entry, `PREVIEW` watermark); lint: missing variables, unsupported CSS; template usage report (which flows use it).
- `render_service.py` — **the API every phase calls**: `documents.render(template_type, entity_type, entity_id, *, template_id=None, register=None, variables_override=None, watermark=None, language=None, issued_by)`:
  1. Resolves template (institution override → platform default, `version` latest published), builds variables from the entity resolver registry (`documents.register_resolver(entity_type, fn)`; phases register theirs), renders HTML → PDF (WeasyPrint, fonts, page size, `ID_CR80` for cards), embeds signed QR (`/verify/{token}`) and barcode when the template has them, signatures/seal images from settings, watermark text.
  2. Register entry: `document_number` from `number_sequences('doc:{type}:{yyyy}')` (or an explicit number passed by the caller, e.g. Phase 18 degree certificate numbers), optional `serial_no` from `document_serials(register)` (`documents.serial_registers`: reserve → used; voids recorded with reason), `content_hash` (SHA-256 of the PDF), `verification_token` (random 32 bytes, unique), `template_id` + version, `entity_type/entity_id`, `person_type/person_id`, `issued_by/at`, `job_id` for bulk; stores the PDF under the tenant prefix with retention policy; emits `documents.issued`.
  3. Idempotent per `(entity_type, entity_id, template_type)` unless `allow_multiple` (e.g. bonafide copies) — re-render returns the current document; **reissue** revokes the old (`revoked_at`, reason) and issues a new one with `superseded_by` link (stored in `revoke_reason` JSON note + new document reference); **revoke** alone marks invalid (verification shows revoked).
  4. Callers migrated in this phase: Phase 07 ID cards & undertakings, Phase 08 offer letters, Phase 14 hall tickets, Phase 15 grade cards, Phase 16 transcripts, Phase 18 degrees/provisional/convocation invitations, Phase 20 allotment letters, Phase 25 event & medical certificates, Phase 12 receipts (optional; thermal path unchanged) — each replaces its direct `pdf_url` write with `render()` and keeps its own FK (`issued_document_id`/`certificate_document_id`).
- `download_service.py` (`documents.watermark_signed_links`): downloads only through `SignedLink` (HMAC, `ttl_minutes` default 15, bound to the requesting user and document; single-use optional); per-download watermark (e.g. "Downloaded by <name> on <date>" + purpose) applied on the fly for sensitive types (transcript, grade card) while the registered hash refers to the unwatermarked original; download counts and audit; public verification never exposes the PDF unless the institution setting `verify_shows_pdf` (masked) is on.
- `bulk_service.py` (`documents.bulk_generation`): jobs for a scope (batch/section/list): ID cards (front/back, photo, QR), bonafide for a batch (purpose variable), course-completion for graduating batch, experience/service letters for staff list, hall tickets/grade cards delegated to Phase 14/15 jobs but using this renderer; progress, partial failures report, ZIP of PDFs via signed link, print-order by roll/serial; concurrency limits per tenant on the `documents` queue.
- `request_service.py` (`documents.certificate_requests`)
  1. Self-service request by student/parent(on behalf)/staff/alumni for allowed types (`request_rules` per type: fee, copies pricing, approver, SLA, `requires_no_dues`, `requires_status` e.g. TC only for `completed|transferred`); fee via `fee_service.create_invoice(payer, source_type='certificate_request', source_id=request)` → `fee_pending` until paid (free types skip); `Idempotency-Key`.
  2. Workflow `certificates.request` (registrar by default; per-type approver: HR for staff types, COE for exam types; optional HOD recommend step); checks at approval: holds (`transcript|all` for transcripts, `all` for TC), no-dues when required (auto-create `no_dues_requests(purpose='transfer')` for TC/migration and wait), duplicate active request for the same type → 409.
  3. `generate` (office/auto on approval when `auto_generate`) → `render()` → `generated`; `issue` → digital (signed link + notification), pickup (pickup slot/notice, signature on collection recorded), post (courier ref); `issued`; rejection with reason and fee refund request (Phase 12) when paid; SLA reminders to the approver; requester timeline.
  4. Alumni requests via alumni portal (Phase 29 reuse) with identity verification (registered email/phone + registration number) — no login-free requests.
- `verification_service.py` (`degrees.verification_portal` and public): unified `GET /verify/{token}` over `issued_documents` for every type (replaces the per-phase implementations from 07/14/15/16/18 which now delegate): validity, type, number, issue date, holder masked (initials + reg. no. masked), institution, `content_hash`, revoked/superseded state; optional hash check by uploading the PDF (`POST /verify/hash`); employer bulk verification with captcha and rate limits; verification log for audit (no PII).
- `registers_service.py` (`documents.serial_registers`): statutory registers (degree, provisional, transcript, TC, migration, bonafide) with reserve/use/void, physical book mapping (book no./page), reconciliation report (issued vs serials), export.
- `stats_service.py`: documents issued by type/month, requests SLA compliance, revenue from certificate fees (Phase 12 by source), pending pickups; feeds Phase 32 (student support metrics).

## 26.11 API verification — `scripts/verify/26_documents.ps1`
Roles: `registrar`, `office.1` (`certificates:issue`), `hr`, `coe`, `hod.cse`, `accountant`, `student.1`, `student.tc` (completed, eligible for TC), `student.hold` (transcript hold), `student.dues`, `staff.1`, `alumni.1`, `parent.1`, `college.admin.b`, `auditor.tmp`, public.
1. Seed `--only documents`; back-fill job → every earlier `pdf_url` row (grade cards, transcripts, degrees, hall tickets, allotment letters, event certificates) has an `issued_documents` entry with `content_hash` and token; `GET /verify/{token}` for a Phase 15 grade card → valid via the unified endpoint; old per-phase verify routes → 308 to unified.
2. Templates: `GET /documents/templates?template_type=bonafide` → platform default + institution override; clone platform → edit blocks (add variable `{{ student.registration_number }}`) → preview with sample → PDF with `PREVIEW` watermark; lint reports an unknown variable → 422 on publish until fixed; publish → version 2; `GET versions` lists both; render uses v2, re-render of an old document keeps v1 (stored `template_id`+version); bilingual template (feature off → 403 on `is_bilingual=true`; on → PDF contains Devanagari block).
3. Render API: `office.1` `POST /documents/render {template_type: bonafide, entity_type: student_program_enrollment, entity_id, register: bonafide}` → `document_number` from `doc:bonafide:{yyyy}`, `serial_no` from register, `content_hash`, token; same call again → same document (idempotent); with `allow_multiple=true` → new copy; `student.1` calling render → 403.
4. Issued register & downloads: `GET /documents/me` as `student.1` → own documents (ID card, grade cards, bonafide); `GET /documents/issued/{id}/signed-link` as `student.1` for own transcript → URL expiring in 15 min; download → PDF with per-download watermark `Downloaded by …` while `content_hash` matches the original stored file; expired link → 410; another user's link → 403 (bound to user); `student.1` requesting a link for `student.tc`'s document → 404; `hod.cse` `GET /documents/issued?template_type=bonafide` → CSE students only; `?template_type=transcript` → 403 (not in department-visible types); `auditor.tmp` list OK, revoke → 403.
5. Revoke/reissue: `registrar` revokes a bonafide with reason → `GET /verify/{token}` → `revoked` with reason; reissue → new document, old shows `superseded_by`; `office.1` revoke → 403 (registrar only per rules); audit rows exist.
6. Serial registers (feature on): reserve 5 serials for `provisional` → `reserved`; render consumes the lowest reserved; void one with reason → `void`; reconcile report shows issued vs used vs void; export job; feature off → render without serial and endpoints 403.
7. Bulk: ID cards for batch 2024 CSE (200) → job progress → 198 ok / 2 failed (missing photo) report → ZIP signed link → files count 198; print order by roll number; second run → idempotent (no duplicates, failed ones retried); course-completion for graduating batch requires `student.graduated` else skipped with reason.
8. Requests: `GET /certificate-requests/types` as `student.1` → allowed types with fees; create `bonafide` (2 copies) → invoice `source_type=certificate_request` amount = fee × copies → `fee_pending`; pay (dev) → `requested` in `registrar` inbox; `hod.cse` recommend step when configured; approve → `auto_generate` → `generated` → `office.1` issue digital → `issued` + notification with signed link; `student.1` timeline shows steps; duplicate active request same type → 409.
9. Request rules: `student.tc` requests TC → `requires_no_dues` → `no_dues_requests(purpose=transfer)` auto-created, request waits; clear no-dues (dev) → proceeds; `student.hold` requests transcript → approval → 409 `HOLD_TRANSCRIPT` shown as blocked with reason; `student.1` requests TC (active student) → 422 `NOT_ELIGIBLE`; `staff.1` requests experience letter → approver `hr` (not registrar); `coe` sees only exam-type requests; rejection with reason on a paid request → refund request created (Phase 12); pickup delivery → pickup notice; `collected` with signature → `issued`; post → courier ref; SLA scan (dev clock) → reminder to approver.
10. Alumni/parent: `alumni.1` requests transcript via alumni identity → allowed; `parent.1` requests bonafide for ward when `allow_parent_requests` → allowed, otherwise 403; `GET /documents/wards` → ward documents.
11. Verification: public `GET /verify/{token}` → masked holder + hash; `POST /verify/hash` with the downloaded (watermarked) PDF → `valid=false` with hint (watermarked copy), with the original file (office download) → `valid=true`; bulk verify with captcha (mock) → results; tampered token → 404; 61st request/min → 429; verification log rows without PII.
12. College scope: `college.admin.b` sees college B issued documents/requests only; overrides for college templates allowed only when setting permits (attempt → 403).
13. Feature gating: `documents.certificate_requests` off → request endpoints 403 while render/issued work; `documents.watermark_signed_links` off → direct signed URL from file service without watermark (documented degraded mode).
