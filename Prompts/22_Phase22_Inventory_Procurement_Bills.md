# PHASE 22 — INVENTORY, PROCUREMENT & BILLS

## Pre-Requisite
Phases 01–12 complete (departments, staff, workflow engine with `procurement.indent` / `procurement.po` templates, number sequences, file service, `rooms` from Phase 10 for asset locations). Phase 23 (`budget_heads`, `ledger_accounts`) is optional: budget checks activate when `accounting.budgets` is enabled; otherwise indents carry no budget head.

## Objective
Stores and procurement for a college/university: item master (consumables, lab chemicals with safety data, non-consumables), multi-store stock with min levels and reorder alerts, **indents** by departments through the approval workflow with budget checks, quotations and comparative statements (GeM/tender references), **purchase orders** with approval and PDF, goods receipts (GRN, partial), stock transactions (issue to departments/labs/persons, returns, transfers, adjustments, write-offs) with a running ledger, **asset register** (tagging, QR labels, custodians, locations, depreciation, condemnation/disposal, physical audits by scan), **vendor bills** with TDS/GST, verification/approval workflow and payment tracking, **supplier registration portal**, and the Orbit-style optional campus vendor store — with department (own indents/issues/assets) vs store keeper vs institution views.

## Feature keys
`inventory.core` (off, standard); `inventory.procurement` (off, standard; depends `workflow.engine`); `inventory.vendor_portal` (off, professional; depends `inventory.procurement`); `inventory.lab_consumables` (off, standard); `inventory.assets` (off, standard); `inventory.asset_qr` (off, standard; depends `inventory.assets`); `inventory.bills` (off, standard; depends `inventory.procurement`); `inventory.vendor_store` (off, standard).

## 22.6 Services
- `master_service.py`: suppliers (GSTIN/PAN validation, categories, rating, blacklist with reason → blocks new POs; bank details encrypted), stores (type, keeper), categories tree, items (code from sequence or manual, unit, consumable flag, hazardous + `safety_data` mandatory when `is_hazardous` and `inventory.lab_consumables`), CSV import; item barcode labels.
- `stock_service.py` (`inventory.core`)
  1. Every quantity change is a `stock_transactions` row and an atomic `stock_levels` upsert under `FOR UPDATE`; negative stock forbidden (409 `INSUFFICIENT_STOCK`); weighted-average `unit_cost_paise` maintained on receipts.
  2. Issue to department/lab/staff/student/event with reference (indent, event, service request); returns; transfers between stores (`transfer_out` + `transfer_in` in one transaction); adjustments and write-offs require reason (+ approval ref above threshold); hazardous issues require the receiver acknowledgement (`safety_ack`) and log for the chemical register.
  3. Low-stock Beat: `quantity < min_stock_level` → `inventory.low_stock` to store keeper + suggested indent (`reorder_qty`); stock ledger per store/item; expiry tracking for chemicals via `safety_data.expiry` (alerts).
- `indent_service.py` (`inventory.procurement`)
  1. Draft → submit → workflow `procurement.indent` (hod → inventory_manager → accounts when `budget_head_id` set and `accounting.budgets` on: step checks `budget_heads.allocated − utilised − committed ≥ estimated` else `changes_requested` with reason); approved → either **fulfil from stock** (store keeper issues; `fulfilled` when all lines issued) or **convert to procurement** (quotations/PO); `committed_paise` increased on approval and released on PO/cancel (Phase 23 event).
  2. Rules: `three_quotes_above_paise` → PO creation blocked until ≥ 3 quotations or a GeM/tender reference is recorded; emergency priority skips quotes with principal approval (recorded).
- `procurement_service.py`
  1. Quotations: manual entry or vendor-portal submission (`inventory.vendor_portal`) against an indent; comparative statement (per-item prices, L1 highlighting, notes); select quotation (audit).
  2. PO: `po_number` from sequence, items with tax → subtotal/tax/total; workflow `procurement.po` (accounts → principal above `po_approval_threshold_paise`); `sent` (email PDF to supplier; portal visibility); amendments create a new version (`version`) before receipt; cancel with reason.
  3. GRN: per PO, per store; partial receipts update `received_qty` and PO `partially_received → received` when complete; rejected quantities recorded; each GRN line → `stock_transactions(receipt)`; non-consumable lines prompt asset creation; GRN PDF.
- `asset_service.py` (`inventory.assets`, `inventory.asset_qr`)
  1. Register from GRN (bulk) or manual: `asset_tag` from sequence per category, custodian, location room, department, cost, warranty, `depreciation_method/rate` from defaults; QR labels PDF (`inventory.asset_qr`) encoding a signed lookup URL; custody transfers with acceptance by the new custodian (notification + accept); status changes (`under_repair` links to service requests Phase 25; `condemned` needs committee/approval ref; `disposed` with sale value → income record event).
  2. Depreciation run per financial year: SLM `cost × rate`, WDV `current_value × rate`; schedule preview; posts `asset.depreciated` for Phase 23 (`expense_records` depreciation head); never below salvage (setting).
  3. Physical audit cycles: start audit for scope (department/room/category) → scans (`asset_audits` rows: found/condition) → report (found/missing/unexpected/condition summary) → missing assets flagged after two cycles; audit due reminders.
  4. Bookable assets flag feeds Phase 25 equipment booking.
- `bill_service.py` (`inventory.bills`): bill entry (supplier, PO/GRN match → three-way check quantities/prices; variance beyond tolerance flagged), GST/TDS computation (TDS section rate from setting per supplier type), workflow `procurement.bill` (verify → approve → principal above threshold), `on_hold` with reason, `paid` with payment ref → emits `inventory.bill_paid` consumed by Phase 23 (`expense_records`, ledger posting); ageing report; supplier statement; vendor portal shows bill status.
- `vendor_portal_service.py` (`inventory.vendor_portal`): self-registration (`suppliers.status='registered'` + `pending_registrations`-style email verification → `portal_user_id` with `vendor` role) → manager verification → `active`; RFQ inbox (indents opened for quotes), quotation submit with file, PO acknowledgement, GRN/bill status; document uploads (GST cert, PAN).
- `vendor_store_service.py` (`inventory.vendor_store`): campus store items with sale price, sales to students/staff (wallet Phase 25 or fee invoice `source_type='vendor_store_sale'`), daily sales report (Orbit vendor inventory parity).
- `reports_service.py`: stock ledger, stock valuation, consumption by department, indent cycle time, PO register, GRN register, supplier performance (on-time, rejections), asset register (statutory format), depreciation schedule, chemical/hazardous register, audit reports; NAAC 4.1/4.4 spend metrics to Phase 32.
