# PHASE 32 — ACCREDITATION & COMPLIANCE (IQAC)

## Pre-Requisite
Phases 01–31 complete (every module that publishes metrics: students, admissions, HR, results, attendance, fees/scholarships, OBE attainment, library, hostel, accounting, events, mentoring/grievances/surveys/clubs, placement, alumni, research, PhD). Phase 33 (committees: IQAC committee, meetings/minutes) and Phase 36 (statutory report renderers) integrate; Phase 40 publishes mandatory disclosures on the website.

## Objective
The quality-assurance backbone: a **framework registry** (NAAC 2024, NBA GAPC v4, NIRF, AISHE, AICTE approval, UGC 2(f)/12(B)) with criteria trees and metric links, a **metric registry** (`app/core/metrics.py`) where every module registers computation functions producing `value + numerator + denominator + breakdown` per period/college/programme, scheduled and on-demand **metric computation** with drill-down to source rows, **manual/override values** with reasons and verification, an **evidence repository** (documents tagged to criteria/metrics/periods, auto-suggested from modules), **accreditation cycles** (NAAC SSR/AQAR, NBA SAR per programme) with criterion responses (narratives, best practices, distinctiveness), ownership, review workflow and exports (SSR/AQAR/SAR formats, NIRF DCF, AISHE DCF), **compliance submissions** tracking (AQAR, NIRF, AISHE, AICTE EoA, UGC annual, NSP returns), **audit registers** (academic/administrative/green/energy/gender/financial/AG) with findings, IQAC dashboards, data-consistency checks (the same student counted once across frameworks), and mandatory disclosure feeds — with department (own metrics/evidence/responses) vs IQAC (all) views.

## Feature keys
`accreditation.aishe` (on, standard); `accreditation.naac`, `accreditation.nirf`, `accreditation.aicte_ugc`, `accreditation.evidence_repo`, `accreditation.audit_registers` (off, professional); `accreditation.nba` (off, professional; depends `obe.attainment`); `accreditation.iqac_cycles` (off, professional; depends `accreditation.naac`).

## 32.6 Services
- `framework_service.py`: frameworks/criteria trees (platform rows, versioned by `version`; institution cannot edit platform criteria but can add custom sub-items in `institution_settings['accreditation.custom_criteria']`), criterion ↔ metric links, period types; framework activation per institution by feature flags (`accreditation.naac` etc.).
- `metric_service.py` — the registry and engine
  1. `app/core/metrics.py` registry: each module registers `computation_key` functions in its `metrics.py` (e.g. `students.enrolment_by_category` in the students module) returning `MetricResult` with breakdown (by category/gender/programme) and a `source_rows_query` for drill-down; derived metrics (`is_derived`, `depends_on`) computed after dependencies; params (e.g. `min_ctc`, `indexing_set`) validated against `params_schema`.
  2. `compute(period, scope)` job (scheduled weekly during the year, on demand before submissions): per key × college × programme as the framework requires; upsert `metric_values(source='auto')` unless an `override` exists (kept with a "stale auto value" note); failures reported per key; period labels normalised (`2025-26`, `2025`, `FY2025-26`); five-year windows for NAAC by aggregating yearly values; consistency checks after compute (see below).
  3. Overrides (`accreditation:override`): reason mandatory, evidence recommended, `overridden_by`; verification by principal/IQAC when `override_requires_verification`; manual inputs for non-computable keys (e.g. green audit outcomes); verification (`verified_by`) locks the value for the cycle; full audit trail (Phase 37) and "auto vs override" diff view for peer teams.
  4. Drill-down: `GET /metrics/{key}/drilldown` returns source rows via the registered query with the caller's visibility (HOD → own department rows; IQAC → all) and PII masking; export as evidence table (xlsx) attachable to a response.
  5. Trends and comparisons (period over period, college vs college in university tenants), threshold alerts (e.g. FSR worsening) to IQAC.
- `evidence_service.py` (`accreditation.evidence_repo`): upload/tag documents (criterion/metric/period, doc type: policy, minutes, certificate, report, photo, MoU…), verification, versioning; **auto-suggestions** from module events (`events.completed` with `naac_criterion`, `research.publication_verified`, `research.mou_signed`, `phd.thesis_awarded`, `placement.stats_published`, `library.reports`, `governance.minutes_approved`, `accounting.statements`) → `EvidenceSuggestion` inbox → accept creates evidence rows linking to `issued_documents`/files; evidence packs (zip per criterion with index) for peer visits; storage quotas; retention 7 years.
- `cycle_service.py` (`accreditation.iqac_cycles`, `accreditation.nba`)
  1. Cycles per framework (NAAC institutional; NBA per programme with `program_id`; AQAR yearly) with period, due date, coordinator, status machine `planning → data_collection → drafting → internal_review → submitted → peer_visit → result` (score/grade recorded).
  2. Criterion responses: one per criterion/metric (UNIQUE), narrative editor (rich text with word limits per framework), linked `metric_value_ids` (auto-filled from the framework's metric keys for the period) and `evidence_ids`; ownership assignment with due dates; workflow `accreditation.response_review` (owner → HOD → IQAC → principal) → `approved` → `final` when the cycle moves to `submitted`; comments/versions; best practices (7.2) and institutional distinctiveness (7.3) as responses; NBA SAR uses Phase 17 attainment tables for criteria 3–4 (auto-filled) and Phase 06/30 for criterion 5.
  3. Exports (job): NAAC SSR/AQAR (docx/pdf per template with QnM tables + QlM narratives + evidence index and hyperlinks), NBA SAR (per programme docx with tables), NIRF DCF (xlsx per discipline), AISHE DCF (xlsx/CSV), AICTE EoA data, UGC annual — through Phase 36 report renderers with this phase's data providers; export files registered as `issued_documents` for traceability; completion % dashboard per cycle.
- `submission_service.py` (`accreditation.aishe`, `accreditation.nirf`, `accreditation.aicte_ugc`): submissions per type/period: generate payload from metrics (job) → review (diff vs previous year) → mark submitted with ack ref and file; due-date reminders; NSP returns from Phase 12; the payload JSON is the source of truth for what was reported (immutable after `submitted`; corrections create a new row).
- `audit_service.py` (`accreditation.audit_registers`): registers per audit type/period (academic & administrative audit, green/energy/environment, gender audit, financial statutory audit, AG audit) with report upload, findings with owners/due dates/status, action taken; Phase 33 `audit_paras` link to `financial_statutory|ag` registers; compliance dashboard; NAAC 7.1.x evidence.
- `consistency_service.py`: cross-framework checks after compute — student headcount equality across NAAC/NIRF/AISHE for the same period, faculty counts vs HR active staff, placed count ≤ eligible, PhD awarded vs Phase 18 awards, expenditure totals vs Phase 23 statements, programme counts vs affiliation approvals; alerts to IQAC with fix links.
- `disclosure_service.py`: mandatory disclosures (AICTE/UGC/NAAC: sanctioned intake, faculty list, fee structure, results summary, placement stats, grievance committees, anti-ragging, IQAC minutes, AQAR links) as a feed for Phase 40 website blocks, refreshed on compute.
- `dashboard_service.py`: IQAC dashboard (cycles progress, criteria completion, verified metrics %, evidence coverage per criterion, submissions due, audits open, consistency alerts, top improvement gaps by NAAC score simulation using `max_score` weights and benchmark bands).
