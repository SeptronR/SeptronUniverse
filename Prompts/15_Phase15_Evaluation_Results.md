# PHASE 15 — EVALUATION & RESULTS

## Pre-Requisite
Phases 01–14 complete (papers conducted, hall attendance with booklet numbers, CIA consolidations locked, grading scales/assessment schemes, arrears, holds, workflow engine, documents templates from Phase 26 are not yet available — grade cards use the platform default template until then).

## Objective
From answer scripts to published, immutable results: bundles and **dummy-number coding** (identity hidden from evaluators; decoding is a separate permission), valuation assignments (internal/external, rounds), question-wise valuations, optional onscreen valuation of scanned scripts, **double valuation** with the discrepancy rule and third valuation, moderation actions approved by the COE, decode → ESE marks, **result processing runs** (config snapshot, checksum) computing grades (absolute/relative), pass rules, grace, **SGPA/CGPA**, class, academic standing and the arrears ledger; verify → approve → publish with **versioned immutable rows**; grade cards, tabulation register, result analysis, notifications; legacy result import for migrating institutions; script custody & retention register.

## Feature keys
`exams.coding_dummy`, `exams.moderation`, `exams.grace`, `exams.script_custody`, `results.processing`, `results.publication_portal`, `results.grade_cards`, `results.rank_lists` (on, standard); `results.legacy_import`, `results.sms_masked_notify` (on, standard); `exams.double_valuation`, `exams.onscreen_valuation`, `exams.relative_grading` (off, professional); `exams.external_examiners` (on, standard).

## 15.6 Services
- `coding_service.py` (`exams:code`): bundles per paper × room/centre (size from setting, default 30) from `exam_attendance(present)` items; `code(bundle)`: generate unique **dummy numbers** (random 6–8 digit with paper prefix; `UNIQUE(bundle_id, dummy_number)`), write `answer_scripts(status='coded')`; the mapping table is readable only through `exams:decode`; custody log entries on create/dispatch/receive/hand-over (`exams:custody`); bundle status machine.
- `valuation_service.py`
  1. `assign(bundles, evaluator, round)`: evaluator = internal staff (not the teacher of that offering unless setting allows) or **external** (`external_examiner` time-boxed user, Phase 02); `valuation_round` 1 (and 2 when session `valuation_mode='double'`); due dates; remuneration; emits `valuation.assigned`.
  2. Evaluator worklist: `GET /valuation/me/bundles` returns scripts as dummy numbers with pages/scan urls (`exams.onscreen_valuation`) — **never** registration ids/names; `submit` marks + question-wise (validated against `exam_papers.qp_pattern` max per question when present); lock on submit; progress; reminders; onscreen annotations stored per script.
  3. `reconcile(paper)`: for double valuation: `discrepancy = |V1 − V2|`; if `> discrepancy_pct × max_marks` → `needs_third` → third assignment (`round 3`, senior evaluator); resolution per `rules.double_valuation.resolution` (`avg_closest_two` default: mean of the two closest of {V1,V2,V3}; `third_final`; `best_two_avg`); single → `computed_marks = V1`; writes `script_final_marks(status='resolved')`.
  4. Moderation (`exams:moderate`): proposals per paper (`scale_up/down`, `add_flat`, `grace`, `normalize`, `cap`) with rule JSON + justification → COE approve → apply → `moderated_marks` + `moderation_delta` per script, `affected_count`; revert allowed before decode.
  5. `decode(paper)` (`exams:decode`, IP allow-list when `security.ip_allowlist_exam_ops`): all scripts `finalized|moderated` → join dummy → `exam_registration_item_id` → write `ese_marks` into a staging table row (`script_final_marks.final_marks` already) and mark scripts `decoded`; audit `exams:decode` with counts; after decode the evaluator projection stays anonymous (mapping never returned by API).
  6. Online papers (Phase 14): quiz total → synthetic `script_final_marks` per item (no bundle).
- `result_service.py`
  1. `create_run(session, scope, run_type)` → `config_snapshot` = merged rules per programme-regulation (Phase 05 `RulesResolver`), grading scale(s), assessment schemes, session settings; status `queued` → job.
  2. Compute (job, per enrolment × registered item): inputs CIA (`cia_consolidations.cia_scaled`, else `MISSING_CIA` anomaly), ESE (`script_final_marks.final_marks` scaled to `ese_max`; absent → `result_status='absent'`; detained items → `detained`; malpractice pending (Phase 16) → `withheld`; hold `exam|all` → `withheld` with `WITHHELD_HOLD`), grace (within `rules.grace` caps; recorded `grace_marks/reason`; anomaly `GRACE_APPLIED`), total/percentage, pass rules (`ese ≥ ese_pass_min_pct`, `total ≥ total_pass_min_pct`, optional CIA min), grade: absolute from `ranges` (boundary ±0.5 → `GRADE_BOUNDARY` anomaly) or relative (`exams.relative_grading`: z-bands over the paper cohort with `min_class_size` fallback), grade point, `counts_toward_cgpa`, `attempt_number/type`; **credit transfers** approved (Phase 07) → rows `attempt_type='credit_transfer'` with mapped grade; audit courses → `audit_pass/fail`; withdrawn items → `withdrawn` (`W`); rows `status='computed'`, `version` = previous current version + 1 for the same (enrolment, course, attempt) else 1, `supersedes_id` set on re-runs; term result: **SGPA** = Σ(Cᵢ×GPᵢ)/ΣCᵢ over credit-bearing registered items (denominator per `include_failed_credits_in_sgpa`), **CGPA** over all `counts_toward_cgpa` rows using `cgpa_attempt_policy` (latest|best) across terms, cumulative credits, backlog count, class from `class_rules` (`first_attempt_only`), `result_class`; `checksum` = sha256 of ordered row hashes; stats; anomalies list; status `computed`.
  3. `verify` (exam cell; checklist ack of anomalies) → `verified`; `approve` (COE; optional `resolution_id` from governance when `governance.minutes`) → `approved`; `rollback` allowed until publish (rows deleted, previous versions untouched).
  4. `publish(run, audience, withhold_ids)`: in one transaction: rows `published` (+ `published_at`, `hash`), previous current versions `superseded/is_current=false`, term results published, `student_term_records` updated (sgpa/cgpa/credits/result_status/status `completed` or `detained`), `student_program_enrollments.credits_earned/cgpa`, **arrears ledger** (fail → `student_arrears` open/attempts; pass on arrear → `cleared` with `cleared_result_id`), academic standing recompute (Phase 07), `abc_credit_ledger(pending)` rows for passed credit-bearing results when `academics.abc_apaar`, `result_publications` row, session status `results_published`; emits `results.published` → notifications (masked SMS: "Result declared. SGPA x.xx" without course detail per `results.sms_masked_notify`), grade-card generation job, Phase 17 attainment trigger, Phase 34 college release; DB trigger guarantees immutability afterwards.
  5. Re-runs after publish (`run_type='revaluation'|'correction'|'supplementary_merge'`) create **new versions** only for affected rows; older rows superseded; term results re-versioned; publication events scoped to affected students.
  6. Queries: `my_results` (published, current versions), public lookup (`reg_no + dob`) when session/setting allows (`audience='public'`), per-offering result sheet for faculty, tabulation register (batch × term), result analysis (pass %, grade distribution, toppers/rank lists — Phase 16 formalises medals), export XLSX/PDF.
- `grade_card_service.py`: per term result → document number (`gc:{yyyy}`), QR token (signed → `/verify/{token}` shows hash + summary), PDF (template: institution branding, grades per course incl. `W/AB/WH/MP/I`, SGPA/CGPA, grace footnote per `print_grace_note`), stored; regenerated on new version (old versions kept, marked superseded on the verify page).
- `legacy_import_service.py` (`results.legacy_import`): XLSX with mapping (reg no, term number, course code, credits, CIA, ESE, total, grade, GP, attempt) → validate (students/courses exist or auto-create retired courses under a `LEGACY` regulation flag, grade in scale) → `run_type='legacy_import'` run → rows `attempt_type='legacy'` published in one step (no verification chain but audited), term results computed from imported rows; rollback deletes the run's rows if nothing newer references them.
- `custody_service.py` (`exams.script_custody`): archive after retention window (setting, e.g., 6 months after publish or after reval window) → `archived`; destruction register with approval (COE) → `destroyed` entries; reports.
- Remuneration: evaluator/moderator/third-valuer lines to payroll on session close (Phase 06 hook, `exams.remuneration`).

## 15.11 API verification — `scripts/verify/15_results.ps1`
Roles: `coe`, `exam.cell`, `decoder`, `faculty.1` (evaluator; teaches paper P1 → cannot evaluate P1), `faculty.5` (evaluator), `examiner.ext` (external evaluator), `hod.cse`, `registrar`, `student.1`, `student.arrear`, `student.hold`, `parent.1`, `auditor.tmp`, public.
1. Seed `--only results` (leaves one paper P2 uncoded/unvalued for the script to exercise).
2. Coding: create bundles for P2 from present items (size 30) → `POST /bundles/{id}/code` as `exam.cell` → scripts with unique dummy numbers; `GET /valuation/bundles/{id}/scripts` as evaluator → **no** `exam_registration_item_id`, names or reg numbers in the JSON (assert keys); custody log dispatch/receive rows.
3. Assign P2 round 1 to `faculty.1` (teacher of P2) → 409 `RULE_VIOLATION` `EVALUATOR_CONFLICT`; to `faculty.5` → 201; round 2 to `examiner.ext` (session double valuation) → 201; `examiner.ext` `GET /valuation/me/bundles` → only own; `faculty.5` submitting marks for a script of a bundle not assigned → 404.
4. Valuations: submit question-wise exceeding `qp_pattern` max → 422; valid → stored; bundle submit locks (`is_locked`) → further edit → 409 `RECORD_LOCKED`.
5. Reconcile P2: scripts with `|V1−V2| > 15 %` → `needs_third` (count matches seeded/entered), third assignment to `faculty.6` → submit → final = mean of closest two (assert numerically for one script); scripts within tolerance → `(V1+V2)/2`.
6. Moderation: propose `add_flat 3` for P2 with justification → `hod.cse` approve → 403; `coe` approve → apply → `moderated_marks` = computed + 3 (capped at max), `affected_count`; revert → restored.
7. Decode: `exam.cell` `POST /exam-papers/P2/decode` → 403; `decoder` from a non-allow-listed IP (feature on) → 403 `PERMISSION_DENIED` code `IP_NOT_ALLOWED`; allow-listed → `decoded_count` = scripts, audit row `exams:decode`; evaluator projection still anonymous afterwards.
8. Run: create `provisional` run for batch 2024 → job → `computed`; anomalies include `MISSING_CIA` for the seeded offering with no consolidation, `ABSENT_WITH_MARKS` for a seeded conflict, `GRACE_APPLIED` rows within caps, `WITHHELD_HOLD` for `student.hold`; `GET rows` for `student.1` → CIA + ESE + total + grade computed per formula (assert against a hand-computed value from seed data), `student.arrear` arrear item `attempt_number=2`; withdrawn item → `withdrawn` grade `W`; audit course → `audit_pass`; a credit-transfer approved in Phase 07 → row `attempt_type=credit_transfer`.
9. Relative grading (feature on) for a paper with cohort ≥ `min_class_size` → z-bands applied; cohort smaller → absolute fallback recorded in `config_snapshot`.
10. SGPA/CGPA: verify `student.1` SGPA = Σ(C×GP)/ΣC from rows (script computes and compares to 2 decimals); `include_failed_credits_in_sgpa=false` on a dev regulation changes the denominator accordingly; CGPA with `cgpa_attempt_policy=best` picks the better of two attempts for `student.arrear`.
11. Chain: publish before verify → 409; verify as `exam.cell` with anomalies unacknowledged → 409; acknowledge → `verified`; approve as `exam.cell` → 403; as `coe` → `approved`; rollback → rows deleted, run `rolled_back`; recreate + verify + approve + publish (audience student, notify) → rows `published` with `hash`, `student_term_records` updated, `student_program_enrollments.cgpa/credits_earned`, arrears: failed course → `student_arrears(open)`, passed arrear → `cleared`; `abc_credit_ledger(pending)` rows for passed credit-bearing results; standing recomputed; session `results_published`; notifications: masked SMS log contains SGPA but no course names; `results.published` event dispatched.
12. Immutability: `UPDATE student_course_results SET letter_grade='O' WHERE id=…` (dev SQL route) → DB error `check_violation`; API has no update endpoint (405).
13. Versioning: correction run for `student.1` course C (marks +5) → new row `version=2`, old `superseded/is_current=false`, term result re-versioned, grade card regenerated; `GET /results/me` shows v2 only with a "revised" flag.
14. Access: `GET /results/me` as `student.1` before publish → empty; after → current published; `parent.1` ward → 200; `faculty.1` `GET /course-offerings/{own}/results` → 200, other offering → 404; `hod.cse` `GET /result-runs/{id}/rows` before verify → 403 (read after verify only) then 200; public lookup with wrong DOB → 404; with correct → summary (when `audience=public`); grade card PDF for `student.1`; `GET /verify/{token}` → hash + SGPA summary; `auditor` reads runs/rows OK, decode/publish → 403.
15. Legacy import: upload XLSX for batch 2023 terms 1–4 (2 invalid grades) → validate report; apply → rows `attempt_type=legacy`, term results computed, CGPA for those students; rollback → removed (no newer references).
16. Custody: archive scripts of the session after publish → `archived`; destroy without COE approval → 403; with → register rows.
17. University tenant: central run scope `college_ids=[B]` publishes only college B rows; `college.exam.coord.b` sees them; college A rows untouched.
