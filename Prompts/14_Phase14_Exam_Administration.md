# PHASE 14 — EXAM ADMINISTRATION

## Pre-Requisite
Phases 01–13 complete (registrations, eligibility snapshots, fees linkage, internal marks/CIA, rooms, HR staff, workflow engine, question bank/blueprints).

## Objective
Everything the Controller of Examinations does **before** valuation: exam sessions (regular/supplementary/arrear/improvement/practical/special) with fee rules and valuation mode, exam papers and the date-sheet with **student clash detection**, exam registration auto-built from confirmed registrations plus open arrears (eligibility snapshot, fees, holds), **hall tickets** (photo, signed QR, offline PDF, optional face-match), seating plans and seat allocations, invigilation roster (auto-assign by availability/load, swaps, remuneration), question-paper management (setters incl. external, encrypted upload, scrutiny, selection, blueprint generation, watermarked print with print log), exam-hall attendance with booklet numbers, malpractice reporting, online/proctored exams via the quiz engine, practical/viva/dissertation paper types, and — for universities — exam centres. Valuation, results and post-result services follow in Phases 15–16.

## Feature keys
`exams.sessions`, `exams.registration_fee`, `exams.eligibility_snapshot`, `exams.hall_tickets`, `exams.clash_detection`, `exams.practical_viva` (on, starter); `exams.seating`, `exams.invigilation`, `exams.qp_management`, `exams.qp_watermark_print_log`, `exams.external_examiners`, `exams.remuneration` (on, standard); `exams.online_proctored`, `exams.face_verification` (off, professional; depends `lms.quizzes` / `integrations.face_verification`); `affiliation.exam_centres` (off, university).

## 14.6 Services
- `exam_session_service.py`
  1. CRUD; `college_id NULL` = central session (university); `exam_kind`; `fee_rules` validation; grading scale defaults from the regulation; `valuation_mode`/`discrepancy_pct` defaults from settings `exams.*`.
  2. Status machine `draft → registration_open → registration_closed → scheduled → in_progress → valuation → result_processing → results_published → closed` (forward only; `scheduled` requires date-sheet published; `in_progress` auto on `start_date` (Beat); `valuation` when all papers `conducted`; later transitions by Phases 15–16); `is_locked` after `results_published`.
  3. `papers_bulk(session)`: from offerings of the term (theory paper per course; practical when `practical_hours > 0` or course type lab; project viva for project types) + arrear-only courses with open `student_arrears` for the college; dedupe; paper codes from sequences (`paper:{session}`).
  4. **Date-sheet**: assign dates/slots/times; `publish_date_sheet` runs **clash detection** (any enrolment with two registered/registrable papers on the same date+slot, considering both regular and arrear papers) → 409 with `ClashReport` unless `force=true` (COE) which records exceptions; emits `exams.date_sheet_published` → calendar events + notifications; also blocks if a paper date is a holiday.
- `exam_registration_service.py`
  1. `build_for_student(session, enrollment)`: regular items = confirmed registration items of the term whose courses have papers in the session (`attempt_type='regular'`, `attempt_number` from arrears history), arrear items = open `student_arrears` with papers in an `arrear|regular(with allow)` session (`attempt_number = attempts + 1`), improvement items when `exam_kind='improvement'` and rules allow; fee per `fee_rules` (per course / per arrear / capped / practical / late after `late_fee_until`); holds check (`exam|all`) reported; status `draft`.
  2. `submit(registration)` (student; `Idempotency-Key`): window open; holds → 409 `HOLD_BLOCKED`; undertakings (Phase 07 gate `exam` when configured); create invoice via `fee_service.create_invoice(payer=student, source_type='exam_registration')` → `fee_pending`; on `fees.payment_received` → `confirmed`; zero-fee → `confirmed` immediately; emits `exam.registration_confirmed`.
  3. Admin create/cancel/debar (`exams:manage`), late registration with late fee; bulk register a batch (job) for regular items; `debarred` when a malpractice punishment applies (Phase 16 sets `debar_until_term_id`).
  4. `apply_eligibility(session, version?)` (`exams:eligibility`): copy the latest (or given) `term_eligibility` version per (term record, offering) into `exam_registration_items.eligibility` and `exam_registrations.eligibility_snapshot`; items `detained/debarred` are excluded from hall tickets and later marked `detained` in results (Phase 15); recompute triggers a new version via Phase 11 when `recompute=true`; summary counts; notifications to detained.
  5. Practical/viva items follow the same registration; project viva item created from `student_projects` (Phase 13).
- `hall_ticket_service.py`: `generate(session, filters, only_missing)` (job, `documents` queue): for each `confirmed` registration with all items `eligible|condoned` (others skipped with reasons) → `hall_ticket_number` from sequence (`ht:{session}`), signed QR token (`hall_ticket_qr_token`), PDF from template (photo, papers with date/slot/venue placeholder until seating, instructions, bilingual), stored; `hall_ticket_issued_at`; release gate `hall_ticket_release_at` (student download blocked before); regenerate after seating to include room/seat; `verify(token)` public → masked identity, papers, validity (revoked when registration cancelled/debarred); optional `no_dues` gate (setting `exams.hall_ticket_requires_no_dues`); emits `exams.hall_ticket_ready`.
- `seating_service.py`: `generate(date, slot, rooms, strategy)`: candidates = confirmed items with `eligible|condoned` for papers at that date/slot; `mixed_course` strategy alternates papers across adjacent seats (minimise same-paper neighbours); `by_course` fills contiguously; respects `rooms.exam_capacity`; deterministic ordering by hall ticket number; writes plans + allocations (`FOR UPDATE` on plan); `publish` → allocations visible to students, hall tickets regenerated with venue; room-wise seating charts PDF and door lists; manual moves with audit.
- `invigilation_service.py`: `auto_assign(request)`: for each (date, slot, room) fill `roles_per_room` from eligible staff (teaching + configured non-teaching), excluding leaves, timetable clashes, staff on other duties, and staff teaching the paper in that room (setting), balancing `max_duties_per_staff` and load; chief/hall superintendents per centre; `swap-request` (staff) → approve by exam cell (validates availability) → `swapped`; `absent` marking; remuneration per role from settings → payroll lines (`staff_payroll_items.source_type='exam_duty'`) on session close (Phase 06 hook) when `exams.remuneration`; duty letters PDF; ICS for staff.
- `qp_service.py`
  1. Assignments per paper × set (A/B/C): internal setter (staff) or **external** (`external_setter` JSON + time-boxed `external_examiner` user via Phase 02 with `exams:qp` on the assignment only); due dates; reminders.
  2. Upload (setter): file encrypted (`INTEGRATION_ENCRYPTION_KEY`-derived per-file key), metadata only visible to COE/exam cell until selection; optional generation from `question_blueprints` (Phase 13 paper builder) → `question_papers` frozen → PDF; scrutiny (subject expert) → approve/reject with remarks; `select` one set (COE) → `selected`; others `rejected`/retained sealed.
  3. Print (`exams:qp_print`): watermark (`{institution} • {paper_code} • {printed_by} • {timestamp}`) burned into the PDF, `question_paper_print_log` row (copies, ip), download token single-use 10 min; every content access audited (`audit_logs.module='exams', action='qp_access'`).
  4. Remuneration for setters/scrutinisers → payroll lines when enabled.
- `hall_attendance_service.py`: per paper/room: mark `present/absent/late/malpractice` with `answer_booklet_number` (unique per paper; scanner-friendly), optional `face_match_score` via `FaceVerifier` adapter (`exams.face_verification`) against the student photo (consent recorded); absent items → `status='absent'` (Phase 15 result `absent`); malpractice report → `malpractice_cases(status='reported')` (Phase 16 handles inquiry) and item `status='malpractice'`; hall attendance sheets PDF.
- `online_exam_service.py` (`exams.online_proctored`): paper `paper_type='online'` linked to a `quiz` (Phase 13 engine) with proctoring options (fullscreen, tab-switch limit, webcam snapshots interval when adapter present); eligible confirmed items get quiz access in the paper window; attempts auto-score → Phase 15 imports as ESE marks (`script_final_marks` synthetic).
- `exam_centre_service.py` (university tenants): centres per session (college, code, chief superintendent, capacity, assigned colleges); registrations routed to centres; seating per centre; bundles per centre (Phase 15).
- Calendar/notification hooks: date-sheet → `calendar_events(event_type='exam')` for students/faculty; reminders D-1 per paper.
