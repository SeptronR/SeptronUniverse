# PHASE 34 — AFFILIATION MANAGEMENT (UNIVERSITY TENANT)

## Pre-Requisite
Phases 01–18 complete (multi-college tenancy with `colleges.college_type` (constituent/affiliated/autonomous/campus/study_centre) and college-scoped roles, programmes with `exam_authority`, fees with `payer_type='college'`, workflow engine with `affiliation.application`, exam engine with central sessions and `exam_centres` (Phase 14 created the centre CRUD under `affiliation.exam_centres`), CIA consolidation with `submitted_to_university` (Phase 13), results per college (Phase 15), documents (Phase 26) for affiliation orders, governance (Phase 33) for Academic/Executive Council resolutions on affiliation decisions). Phase 32 reads affiliation metrics; Phase 40 publishes the affiliated-college list.

## Objective
The university ↔ affiliated-college relationship: **college registry** enrichment (affiliation number, since, type transitions incl. autonomy, AISHE/AICTE ids, principal, exam-centre status), **affiliation applications** per academic year (new/renewal/extension/intake increase/programme addition/closure/autonomy) with document checklists, fee schedules and invoices, **scrutiny → inspection** (committee constitution, scheduling, report upload, deficiency list, compliance) → **decision** (approve/conditional/reject) with orders (Phase 26 template, resolution-linked), **programme approvals** with sanctioned/lateral intake and validity that gate Phase 08 seat matrices and Phase 09 registrations, **college data submissions** per term/session (student registrations, course registrations, CIA marks, attendance eligibility, practical marks, exam registrations, internal faculty list) with validation, verification/return/acceptance and the **lock that gates central result processing**, **exam centres** per session (allocation of colleges, chief superintendents, capacity, script bundle routing), college dashboards (compliance, dues, submissions, results release), university-side portfolio dashboards and statutory returns (affiliated colleges list, intake, results by college) — with college (own) vs university office (all) views.

## Feature keys
`affiliation.core` (off, university tier; depends `institution.multi_college`); `affiliation.inspections`, `affiliation.data_submissions`, `affiliation.fees` (depend `affiliation.core`, `fees.core`); `affiliation.exam_centres` (depends `exams.sessions`) — all off by default, university tier. Standalone/autonomous college tenants never enable these; a university tenant with `institution.multi_college` enables them for the affiliation office.

## 34.6 Services
- `college_registry_service.py` (`affiliation.core`): enrich Phase 03 colleges with affiliation fields; type transitions (`affiliated → autonomous` on an approved `autonomy` application: sets `programs.exam_authority='autonomous_college'` for the college's programmes from the effective year, keeps university degree awarding; `constituent`), principal assignment (college role), exam-centre flag, AISHE/AICTE ids; college document vault (statutory approvals) with expiries; compliance score (approvals valid, dues, submissions on time, deficiencies closed).
- `application_service.py` (`affiliation.core`, `affiliation.inspections`, `affiliation.fees`)
  1. College creates per year/type with programmes and the document checklist for the type (completeness check blocks submit); `affil:{yyyy}` number; submit → fees computed from `affiliation_fee_schedules` (`flat`, `per_program`, `per_student` × requested intake) → `fee_service.create_invoice(payer_type='college', payer_id=college, source_type='affiliation_application')` → `fee_paid` on payment (offline/online via Phase 12); workflow `affiliation.application` (variant by type): registrar scrutiny (`proceed|return` with missing documents → college resubmits) → inspection (when required by type/last-inspection age) → decision.
  2. Inspection: constitute committee (internal staff + external experts; Phase 33 committee optional), schedule date/mode, notify college; committee members upload report with findings (deficiencies with severity) via their portal; deficiency notice (Phase 26) → college responds within `deficiency_compliance_days` with evidence → verifier closes each; re-inspection when critical deficiencies remain; inspection fee per schedule.
  3. Decision (`affiliation:decide`; VC step; Academic/Executive Council resolution link when `governance.minutes` and type requires): `approved|conditional|rejected` with conditions, per-programme sanctioned/lateral intake and validity → upsert `affiliation_program_approvals` (UNIQUE per college/programme/year), affiliation order PDF (`order:{yyyy}`, Phase 26, resolution cited), college fields updated (`affiliated_since`, `affiliation_number` for new), programme creation for `program_addition` (Phase 05 `programs` rows for the college with `exam_authority` per college type), closure handling (`program_closure`: blocks new admissions, existing batches continue — Phase 08/09 checks), autonomy transition; notifications; appeal/review request as a new application type `extension` with reference (setting).
  4. Withdrawal by college before decision; expiry tracking of orders/approvals with renewal reminders (`affiliation.program_approval_expiring` 90 days before `valid_to`); portfolio dashboards.
- `program_approval_service.py`: authoritative intake per college/programme/year consumed by Phase 08 (`seat_matrix` total ≤ `sanctioned_intake + lateral_intake`; admissions beyond → 409 `INTAKE_EXCEEDED`), Phase 09 (registrations only in approved programmes for the year), Phase 32 (`affiliation.colleges_count`, intake metrics), Phase 40 (public list of approved programmes per college); manual updates (withdrawal, conditions) with reason and audit; validity chips; bulk carry-forward at year rollover (Phase 03 `rollover_academic_year.py` hook creates next-year provisional rows for permanent approvals).
- `submission_service.py` (`affiliation.data_submissions`)
  1. Submission windows per type from term/session dates; college prepares a submission either **from system data** (extractor per type: `student_registrations` from active term records; `course_registrations` from locked registrations; `cia_marks` from `cia_consolidations(status='submitted_to_university')` for the session's papers; `attendance_eligibility` from `term_eligibility` decisions; `practical_marks` from practical paper internal/ESE components; `exam_registrations` from confirmed registrations; `internal_faculty_list` from active staff with workload) or **file upload** (CSV/XLSX through `data_imports` with mapping) for colleges not using the system fully; validation (`submission_validation_rules`: every registered student has CIA for every registered paper, marks within max, eligibility decided for all, faculty list matches offerings) → report; `record_count`.
  2. Status machine `draft → submitted → verified (university verifier) → accepted (COE for exam types / registrar for others) → locked` with `returned` (remarks; college fixes and resubmits — new version, history kept); `locked` freezes the college's underlying data for that term/session (Phase 13 CIA lock, Phase 11 eligibility freeze, Phase 14 registration close) and unlock requires COE with reason (audited); **result gating**: Phase 15 `result_processing_runs` for a central session refuses colleges whose required submission types are not `accepted|locked` (`affiliation.results_require_accepted`) — the run reports per-college gating status; compliance dashboard (on-time %, returns count) per college; reminders before due and escalation after.
  3. Post-result: university publishes per college; college receives release status; college-side reports (Phase 16 rank lists per college) unaffected.
- `exam_centre_service.py` (`affiliation.exam_centres`): centres per central session (college as centre, code, chief superintendent from the centre college staff or university observer, capacity with buffer), allocation run assigning colleges to centres (`nearest` by college address geo, `capacity`, or manual) → `exam_registrations` routed (Phase 14 seating per centre; hall tickets show centre), centre appointment letters (Phase 26), centre-wise material dispatch lists (question papers via Phase 14 print log, script bundles per centre via Phase 15 `answer_script_bundles.exam_centre_id`), centre remuneration lines (Phase 06/14), observer reports; centre dashboard for `college_exam_coordinator` (registrations, seating, attendance, bundles dispatched/received).
- `dashboard_service.py`: college dashboard (profile/approvals/applications/dues/submissions/results release/inspections/compliance score) and university portfolio (by type/status, inspections due, deficiencies open, dues by college, submissions compliance %, results gating per session, expiring approvals); statutory returns (affiliated colleges list with intakes for UGC/state, Phase 36) and website list (Phase 40).
