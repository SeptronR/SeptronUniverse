# PHASE 40 — PUBLIC WEBSITE, COURSE CATALOGUE, ADMISSION PORTAL ENTRY & MARKETING SITE

## Pre-Requisite
Phases 01–39 complete (Phase 03 institution profile/branding and public settings; Phase 05 programmes/regulations/curriculum with `academics.public_catalog`; Phase 08 admission cycles, applicant flow (`/apply/:cycle`) and enquiry CRM; Phase 12 public fee structures flag; Phase 25 events; Phase 26 `/verify/:token` endpoint; Phase 15/16 result public lookup setting; Phase 32 mandatory disclosures feed; Phase 33 approved policies and committees; Phase 34 affiliated colleges/approved programmes; Phase 35 public counters; Phase 38 self-serve registration/demo requests and plans; Phase 39 branding/manifest service; Phase 44 wires Traefik/nginx host routing and TLS for custom domains — this phase ships the application side).

## Objective
A per-institution **public website** rendered by the platform (server-side rendered React routes under `/site/:slug/*` and on **custom domains**), built from `institution_website_config` (theme, hero, ordered sections, SEO, contact, social) and content: **pages/content items** by section, **notices** (categories, publish/expiry, attachments, RSS), **events** (mirrored from Phase 25 or manual), **gallery** (albums/images), **enquiry forms** (captcha, rate limits → enquiry CRM), **mandatory disclosures** (Phase 32 feed, policies, committees, RTI/PIO, anti-ragging, IQAC/AQAR, affiliated colleges, approved programmes), leadership/accreditations from the profile, public counters (Phase 35), a **course catalogue** (programmes → regulations → term-wise curriculum → course pages with syllabus/outcomes, electives, fees summary, intake, eligibility, admission CTA; JSON-LD; search), the **admission portal entry** (open cycles, apply/login, status), **public verification** (documents, results lookup when enabled, affiliated-college verification of programmes), **custom domains** (DNS TXT verification, primary domain, SSL status via the edge, host → institution resolution), SEO (sitemap/robots/OG/meta), privacy-friendly analytics, page caching with invalidation on publish, accessibility, and the platform **marketing site** (`/`, features, pricing from plans, demo request, sign-up → Phase 38 registration, docs/status links).

## Feature keys
`website.core` (on, starter), `website.enquiry` (on, starter; depends `admissions.enquiry_crm`), `website.course_catalog` (on, standard; depends `academics.public_catalog`), `website.custom_domain` (off, standard; depends `website.core`); uses `admissions.online_application` (apply entry), `degrees.verification_portal` (verify page), `events.core` (events mirror), `accreditation.*` (disclosures). Marketing site is platform-level (no tenant key).

## 40.6 Services
- `site_service.py` (`website.core`)
  1. Config CRUD with **draft → preview → publish**: edits save to `institution_website_config` as draft (`sections` JSON carries `draft` and `published` copies); preview via signed token URL (`/site/:slug?preview=<token>`); publish copies draft → published, bumps `updated_at`, invalidates cache, writes audit (version history from audit diffs; rollback to a previous published version).
  2. Rendering: `render(institution, path)` assembles section data (hero, about from `institution_profile.vision/mission`, leadership (head name/title/photo), programmes (catalogue teaser), admissions CTA (open cycles), notices (latest N per category), events (upcoming), gallery, stats (Phase 35 public counters + Phase 32 disclosures numbers), accreditation badges (profile `accreditations`), placements (Phase 28 aggregate stats), research highlights (Phase 30 counts), departments/colleges (with sub-pages), faculty directory (allow-listed fields), disclosures, policies, committees (names/roles/contacts published by Phase 33), contact/map, footer) → SSR HTML via the React server renderer (`frontend/src/site/*` shared components) with `seo` meta/OG/JSON-LD (`CollegeOrUniversity`, `Course`, `Event`) → cached in Redis per `(institution, path, locale)` with `website.cache_ttl_seconds` and ETag; invalidation on publish/notice/event/gallery/catalogue/disclosure changes (consumers); `Cache-Control: public, max-age=300, stale-while-revalidate=600` for the edge.
  3. Host resolution middleware extension (Phase 01 `InstitutionContextMiddleware`): `Host` header → `institution_domains(verified, ssl active)` → institution; else `/site/:slug`; platform hosts serve the marketing site; unknown host → 404 page; `X-Institution-Slug` passthrough from nginx/Traefik (Phase 44); redirects to the primary domain when set (301) and `www` normalisation.
  4. Content items: markdown/HTML sanitised (`bleach` allow-list: headings, lists, links (nofollow external), images from the file service, tables, embeds allow-listed (YouTube/Maps)); sections `college:{code}`/`department:{code}` create sub-sites `/site/:slug/colleges/:code`, `/departments/:code`; locale variants when `i18n.web`.
  5. Notices: categories, scheduled publish/expiry (Beat), pinning, attachments (file service, public signed-less path under `public/` prefix with immutable names), RSS feed per institution/category, optional push to Phase 24 announcement (`also_announce` → audience students/staff), archive page with year filter, search.
  6. Events: mirror from Phase 25 `events(status in scheduled|completed)` by selection (`event_id`) with images and public registration link when `registration.open` (Phase 25 external registration form), manual events; iCal for the public calendar (Phase 25 institution feed).
  7. Gallery: albums/images (thumbnails via file service, EXIF stripped, max sizes), bulk upload job (zip), ordering, cover, publish.
  8. Site analytics: privacy-friendly counters (Redis HyperLogLog per page/day, referrers coarse) shown to admins; optional external provider script (Plausible/GA4 id) injected only when set (consent banner for GA4 via Phase 43 cookie policy).
- `enquiry_service.py` (`website.enquiry`): public form with captcha (Phase 01 rate limiter/captcha), honeypot, rate limit `website.enquiry_rate_limit` per IP, spam heuristics (links count, disposable domains) → `website_enquiries` → create/link Phase 08 `enquiries` (`source='web'`, `program_interest`) when `admissions.enquiry_crm` → notifications to admissions officer + acknowledgement email/SMS to the enquirer (DPDP notice text version recorded); status sync from CRM (`enquiries.stage`) via events; export; DSAR/erasure honoured (Phase 43).
- `catalogue_service.py` (`website.course_catalog`, `academics.public_catalog`)
  1. Programme list (visible, grouped by college/level/department; filters level/mode/department; search), programme page (overview, eligibility (from `admission_cycle_programs` when a cycle is open else regulation text), intake (Phase 34 approvals for affiliated colleges else `programs.sanctioned_intake`), duration/terms, current regulation summary, term-wise curriculum from `program_structure_terms → curriculum_courses → courses` (credits, L-T-P, course type), elective baskets, PO/PSO when `show_outcomes` (Phase 13 `outcome_definitions`), fees summary when `website.catalog_show_fees` and the programme's `show_fees` (from Phase 12 structure totals per year, "indicative"), admission CTA (open cycle → `/apply/:cycle`), JSON-LD `Course`/`EducationalOccupationalProgram`), course page (syllabus units, outcomes, references, prerequisites, offered-in terms), department/faculty listing, printable programme brochure (Phase 36 renderer, job), sitemap entries; `CatalogueSettings` editing (visibility per programme/course, highlights, show flags); consistency with Phase 34 (approved programmes only for affiliated colleges).
