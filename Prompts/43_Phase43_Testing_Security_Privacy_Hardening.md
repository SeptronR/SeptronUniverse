# PHASE 43 — TESTING, SECURITY & PRIVACY HARDENING

## Pre-Requisite
Phases 01–42 complete (every phase shipped `scripts/verify/NN_*.ps1`, a UI checklist and the structural guards from `00_PREREQUISITE` §6; Phase 02 shipped auth/MFA/sessions/IP allow-lists/masking/consents/DSR stubs; Phase 37 shipped audit integrity, security events, retention/archival and `retention_service.erase`; Phase 41 shipped user/tenant exports; Phase 36 provides renderers for evidence packs; Phase 44 will run the pipelines this phase defines). `docs/Authorization_and_Visibility.md` §7, `docs/Technical_Architecture.md` §11/§17 and ADR 0006 (functional verification, no unit tests) are the contracts.

## Objective
Prove and harden the whole system before launch — **without unit-test suites**: a **verification runner** that executes every phase's API script per role in order against a fresh seed (with JUnit-style reports for CI), **Playwright suites per round** (portals and admin sweeps with axe accessibility checks), **isolation/scope/visibility checks** (RLS raw-SQL, cross-tenant, college scope, every role × module list expectation from the matrix), **authz/feature audits** (every route gated; feature-disabled → 403 + hidden nav/tab), **immutability checks** (published results/term results triggers, issued documents, locked marks, finalized attendance), **golden data** (SGPA/CGPA/attainment/eligibility/fee computation cases run through dev compute endpoints and compared), **load tests** (k6: registration rush, result publish fan-out, hall-ticket bulk, list p95, dashboard p95) with pass thresholds from `docs/Technical_Architecture.md` §17, **security hardening** (headers/CSP, CORS per env, rate limits, upload limits, JWT RS256 rotation, MFA enforcement report, session policies, IP allow-lists, API-key hygiene, secrets scanning, dependency/SAST/container scans in CI with SBOM, encryption-at-rest for `*_encrypted` columns with key rotation, backup encryption, PII-free logs), **privacy/DPDP** completion (consent banner + versioned notices per portal/website, purpose-wise consents incl. guardian consent for minors, data-subject requests end-to-end (access/export/correction/erasure) with due dates and privacy-officer workflow, PII inventory and masking audit across schemas, retention verification, data-processing register, breach-notification runbook), **VAPT** preparation and remediation tracking (OWASP ASVS L2 checklist, scope, findings CSV, retest gate), **ISO 27001-readiness** checklist (Annex A mapping to platform controls with evidence links), the complete **demo institution seeder** by type (`--type university|autonomous|affiliated --all`), the **access matrix** (`gen_access_matrix.py` → `docs/Access_Matrix.csv` reviewed against `docs/Roles_and_Permissions.md`), and the filled **QA plan** (`QA_Test_Plan.md` with per-role sweeps and a CSV findings log; skeleton from Batch I).
