## Pre-Requisite
Phases 01–43 complete (Phase 00 shipped the Dockerfile skeleton, `docker-compose.yml` (dev), `nginx/nginx.conf`, `guards.yml`, `build.yml`, `frontend-*.yml` stubs; Phase 01 shipped `/health`, `/ready`, `/metrics`, JSON logging, Sentry init, partition maintenance and read-only mode; Phase 37 shipped retention/archival; Phase 38 shipped platform settings, announcements, status inputs and demo reset; Phase 40 shipped the custom-domain edge endpoints; Phase 42 documented the mobile release lanes; Phase 43 shipped the verification runner, security scans and posture; Batch I supplied `RUN_AFTER_PHASE.md`, `.claude/launch.json`, `docker-compose.yml`, `nginx/nginx.conf`, `.gitignore`, `.github/workflows/*` and the skeletons of `QA_Test_Plan.md`/`Real_World_Launch_Plan.md`). ## Objective
Make SeptronUniverse **deployable, observable and operable** at the §17 targets: production **Dockerfiles** (backend multi-stage with WeasyPrint libs and non-root user; frontend static + SSR node image; worker/beat/flower from the backend image), **`docker-compose.prod.yml`** (backend gunicorn/uvicorn workers, Celery workers per queue with concurrency, beat, flower behind auth, SSR service, nginx or Traefik labels, PostgreSQL with tuned config + pgbouncer, Redis with persistence/maxmemory policy, ClamAV optional, backup sidecar), **GitHub Actions** (`guards.yml` + `security.yml` (Phase 43) + `verify.yml` (nightly `api_all`, per-PR rounds) + `build.yml` (image build → tests/guards → push `ghcr.io/septronr/universe-api:{env}-{sha}` + `universe-web` → `repository-dispatch` to `orbit-infra` with tags) + `frontend-build.yml`/`frontend-deploy.yml` (branch → mode → target) + `mobile-release.yml` (Fastlane/Codemagic lanes) + `release.yml` (semver tags, changelog, SBOM, release notes → platform announcement)), **expand/contract migrations** with a lint and a lock-protected `alembic upgrade head` in the backend container (workers `RUN_MIGRATIONS=0`), **zero-downtime rolling deploys** (readiness-gated, optional read-only window for risky migrations, rollback procedure), **environments** (dev/demo/staging/prod with per-env `.env`, feature-flag defaults, nightly demo reset), **backups & DR** (base backups + WAL archiving with `pgbackrest`/`wal-g` to S3-compatible storage, per-tenant logical export job (Phase 38), uploads versioning, encryption, retention 30 daily/12 monthly, **quarterly restore drill** script and runbook proving RPO 15 min / RTO 4 h), **monitoring & alerting** (Prometheus + Grafana dashboards, alert rules for error rate/p95/queue depth/outbox lag/DLQ/DB connections/disk/cert expiry/backup age/webhook failure rate/health probes; Sentry; uptime checks; log shipping (Loki) with request/tenant/user ids; Flower), a public **status page**, **runbooks** for every operational scenario, **ops scripts** (year rollover, term close, archive year, tenant export/restore, key rotation, partition maintenance, cache warm), capacity/performance tuning (indexes from p95 offenders, pool sizes, Celery concurrency, Redis policies, SSR cache), the **release process** (conventional commits → changelog, tags, release notes to institutions, deprecation policy), the completed **`RUN_AFTER_PHASE.md`** and the **`Real_World_Launch_Plan.md`** launch tracker (providers go-live, VAPT, DR drill, training, pilots, legacy cutover via Phase 41), plus chaos/resilience checks (worker kill mid-job, DB failover, Redis restart).

- `docker & compose` (repo)
  1. `backend/Dockerfile`: multi-stage (`python:3.12-slim` builder with wheels → runtime with WeasyPrint libs `libpango-1.0-0 libpangoft2-1.0-0 libcairo2 libgdk-pixbuf-2.0-0 libffi8 fonts-noto` (+ Indic fonts), non-root `app` user, `tini`, healthcheck `curl /health`, `docker-entrypoint.sh`: wait for DB/Redis → `RUN_MIGRATIONS=1` → `python scripts/migrate_with_lock.py` (`pg_advisory_lock(0x554E4956)` → `alembic upgrade head` → `check_schema_drift.py` (warn) → seed platform refresh (`seed_platform.py --refresh` idempotent: permissions/features/plans)) → `gunicorn -k uvicorn.workers.UvicornWorker -w ${WEB_CONCURRENCY:-4} --timeout 60 --graceful-timeout 30 --max-requests 5000 main:app`; workers: `celery -A app.tasks.celery_app worker -Q <queue> -c <n> --max-tasks-per-child 500 --without-gossip` with graceful shutdown (SIGTERM → finish current task ≤ 60 s; jobs mark `interrupted` and are re-queued idempotently); beat with `RedBeat`/DB lock (single instance); flower behind basic auth.

  4. `orbit-infra` integration: `compose/apps/universe-{dev,demo,prod}.yml` templates with Traefik labels (routers for `api.`, `app.`, `*.sites` custom domains via the Phase 40 `GET /internal/domains` provider → Traefik file/HTTP provider config generated by `scripts/ops/gen_traefik_domains.py` on a 5-minute cron; ACME DNS/HTTP challenge per host; `ssl-status` callback), middleware (rate limit, headers, compress), and the `repository-dispatch` receiver workflow that pulls the image tags and performs the rolling update (`docker compose pull && up -d --no-deps --wait backend` replica by replica, then workers, then beat), with automatic rollback to the previous tags when readiness fails; `nginx/nginx.conf` kept for single-host deployments (`/api/`, `/ws/`, `/uploads/`, `/site/` → SSR, security headers, 25 MB body, `X-Institution-Slug $host`).
- `migrations_service` (`scripts/check_migration_safety.py` + process)
  1. **Expand/contract lint** (CI): a revision may not `DROP COLUMN/TABLE`, `ALTER TYPE`, add `NOT NULL` without default, rename, or create indexes non-concurrently on large tables in the same release as the code that stops using the old shape; destructive steps go in a follow-up revision tagged `contract` and require a `# contract-of: <revision>` marker + a `RELEASE_NOTES` entry; large index creation uses `CREATE INDEX CONCURRENTLY` (outside the transaction, `op.get_context().autocommit_block()`); data backfills run as jobs, not migrations, when > 1 M rows.
  2. `alembic heads` = 1; `migrate_with_lock.py` serialises across replicas; migration duration logged; risky migrations (flagged `# risky`) require the deploy to open a read-only window (Phase 38 schedule, auto-announced) and are run first; `alembic downgrade` tested for the last 5 revisions in CI on the ephemeral stack; schema drift check post-migration; `Database_Schema.sql` updated with every delta so a fresh install equals an upgraded one (CI compares both paths' `information_schema` dumps).
- `cicd_service` (`.github/workflows/*`)
  1. `guards.yml` (Phase 00) + `security.yml` (Phase 43) run on every PR; `verify.yml`: spins the ephemeral stack (`docker compose -f docker-compose.ci.yml`), seeds the demo institution, runs `scripts/verify/run_all.py --suite api_round_<n>` for rounds touched by the diff (path mapping) and `e2e` round suites, uploads JUnit/HTML/axe reports; nightly `api_all` + `e2e all` + `visibility` + `immutability` + `golden` on staging; weekly load scenarios on staging with threshold gates → results to Phase 43.
