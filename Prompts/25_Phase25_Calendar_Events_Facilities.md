# PHASE 25 — CALENDAR, EVENTS & FACILITIES

## Pre-Requisite
Phases 01–12 complete (years/terms/holidays, rooms/buildings from Phase 10, students/staff, fee linkage, workflow engine with `event.approval` and `facilities.room_booking` templates, push channel). Phase 22 (`assets`, `suppliers`) enables equipment booking and AMC; Phase 24 (`comms.emergency_broadcast`) enables SOS escalation to broadcast; Phase 26 issues event certificates (until then a platform template is used); Phase 20 hostel complaints link to service requests.

## Objective
The campus calendar and the "estate" services: an **academic calendar** aggregated from terms, exams, registration windows, holidays and events with institution/college/personal **iCal feeds** (Google/Outlook), **events** (conferences, FDPs, guest lectures, cultural, sports, outreach, alumni, convocation) with proposal → approval → budget → registrations (fee) → attendance → certificates → report (NAAC criterion tagging), **room and equipment booking** with conflict checks and approvals, **service desk** (maintenance/IT tickets with SLA, assignment, vendor/AMC linkage, ratings, lost & found), **AMC contracts**, **visitor & gate passes**, **emergency/SOS alerts** from the mobile app with responder dispatch, **health centre** (confidential visits, insurance) and **counselling appointment slots**, **sports** (teams, events, participation with achievement evidence), and optional **canteen prepaid wallet** — with self (my bookings/tickets/appointments) vs officer (all) views.

## Feature keys
`calendar.core`, `calendar.ical` (on, starter); `calendar.personal_feed` (on, standard); `events.core` (on, standard); `events.certificates` (on, standard; depends `documents.templates`); `facilities.room_booking` (on, standard; depends `timetable.rooms`); `facilities.service_desk` (on, standard); `facilities.equipment_booking` (off; depends `inventory.assets`); `facilities.lost_found` (off); `facilities.amc` (off; depends `inventory.assets`); `facilities.visitor_gate` (off); `facilities.emergency_sos` (off; depends `mobile.app`, `comms.push`); `facilities.health_centre` (off); `facilities.counselling_appointments` (off; depends `mentoring.counselling` — Phase 27 links referrals; slots/bookings work standalone); `facilities.sports` (off); `facilities.canteen_wallet` (off, professional; depends `integrations.payments`).

## 25.6 Services
- `calendar_service.py` (`calendar.core`, `calendar.ical`, `calendar.personal_feed`)
  1. Sources merged read-only into the calendar: `academic_terms` (start/end, registration/add-drop/last instruction), `holidays`, `registration_windows`, `exam_sessions/exam_papers` (date-sheet), `events(scheduled|completed)`, `room_bookings(approved)` (facilities view), `class_sessions` (personal), `hostel_leaves` (personal), meetings (Phase 33), placement drives (Phase 28) — via a source registry (`calendar.register_source(key, query_fn)`); manual `calendar_events` for anything else with `audience_rules`.
  2. Institution/college iCal feeds (`/calendar/ical/{institution|college}.ics`, public or token), **personal feed** with revocable token (`calendar_feed_tokens`; `webcal://` URL; includes my timetable, exams, bookings, registered events, deadlines); reminders (push/email) per user preference (`calendar.reminder` T-1 day/T-1 h).
  3. Academic calendar PDF (year at a glance) generation; term-wise deadline list for the student Home widget; conflicts warning when an event overlaps an exam day for the same audience.
- `event_service.py` (`events.core`, `events.certificates`)
  1. Proposal → workflow `event.approval` (hod → principal); budget > 0 with `accounting.budgets` → `event.budget` step (accountant) → `budget.commit_requested`; approved → `scheduled` (venue booking auto-created as `room_bookings(event_id)` and approved if free, else conflict returned); cancel releases venue/budget.
  2. Registrations: internal (student/staff) or external (public form when `registration.open` and `website.core`), capacity, fee via `fee_service.create_invoice(payer=person|external, source_type='event_registration')`, QR ticket; waitlist when full; reminders.
  3. Attendance by QR scan (organiser) or list; **certificates** job for attended registrants using `document_templates(template_type='event_certificate')` → `issued_documents` (Phase 26 renderer; platform default template until then) with verification QR; speakers/organisers certificates optional.
  4. Completion: report (participants, external count, spend vs budget from Phase 23 expenses tagged to the event, images, outcomes), `naac_criterion` tagging and `report_url`; feeds Phase 32 evidence (`accreditation.evidence_suggested`) and Phase 27 activity hours (`clubs.activity_hours_credits` when the event is club-linked); Phase 18 convocation events are `event_type='convocation'` rows created by Phase 18.
- `booking_service.py` (`facilities.room_booking`, `facilities.equipment_booking`)
  1. Room availability = not blocked by `timetable_entries` (published timetable for the term, day/slot → time), `class_sessions` (rescheduled/extra), approved bookings, exam seating plans (Phase 14) and room `status`; request with `booking_lead_hours`; auto-approve for `auto_approve_roles` within own department rooms (`rooms.department_id`) else workflow `facilities.room_booking` (estate_officer; room owner department HOD first when `rooms.department_id` set); approval re-checks conflicts under `FOR UPDATE` → 409 `ROOM_CONFLICT`; cancellation by requester; recurring bookings (weekly N weeks) as a batch with per-instance conflicts; calendar entries for approved bookings; usage report per room.
  2. Equipment: `assets.is_bookable` items (projectors, cameras, lab instruments, vehicles when Phase 21 exposes) → request → custodian → estate officer (`facilities.equipment_booking` workflow); handover/return check with condition; overdue return reminders.
- `service_desk_service.py` (`facilities.service_desk`, `facilities.amc`, `facilities.lost_found`)
  1. Ticket `ticket_number` from sequence `sr:{yyyy}`, category → `sla_due_at = now + sla_hours[category]` (priority `high` halves, `urgent` quarter); attachments; auto-routing rules (category → default assignee/team from settings; `it` → IT cell, `security` → security officer); assignment (staff or vendor with AMC contract when asset/category covered — `amc_contracts.sla` overrides SLA), status machine `open → assigned → in_progress → resolved → closed` (auto-close 3 days after resolved unless reopened), reopen by requester within 7 days, rating on close; SLA breach Beat → escalation to estate officer/HOD; cost capture → Phase 23 expense (optional); linked entities (`hostel_complaints.service_request_id`, `assets.status='under_repair'` from Phase 22 on `asset` category with `asset_id` in attachments/meta); kanban and SLA dashboard; CSAT and MTTR metrics.
  2. AMC contracts: register per supplier/asset category/assets with SLA, value, period, documents; expiry reminders (60/30 days); service requests under AMC tagged for vendor performance report.
  3. Lost & found: report found item (photo/location) → claims with identity check → `claimed`; disposal after retention (setting) with log.
- `visitor_service.py` (`facilities.visitor_gate`): passes pre-registered by hosts (staff/students-with-permission) or issued at gate by security/receptionist (`facilities:manage` gate); `pass_code`/QR; gate scan in/out with photo optional; `inside` list for evacuation; expiry; host notified on arrival; blacklist check (setting list); daily register export; DPDP: visitor PII retention 90 days (purge job).
- `emergency_service.py` (`facilities.emergency_sos`)
  1. Mobile SOS button (student/staff/parent-on-campus): `emergency_alerts(raised_by, alert_type, location{lat,lng,accuracy}, message)`; responders resolved from settings by type and college/campus polygon; push + SMS to responders with map link; escalation every `sos_escalate_minutes` until `acknowledged`; responder `acknowledge` (who/when) and `resolve` with notes; raiser sees status; false-alarm marking; drills; integration with Phase 24 emergency broadcast for `fire|security` when `comms.emergency_broadcast` (optional one-tap escalation); safety register export; rate limit/abuse detection (repeat false alarms → discipline note Phase 27).
- `health_service.py` (`facilities.health_centre`): confidential visits recorded only by `health:record` (medical_officer/nurse): complaint/diagnosis/treatment/referral; person sees own visits; HOD/warden may see **only** "visited on date, fitness certificate issued" summary when the person consents (setting); medical certificates → Phase 26 template (`medical_certificate` custom type) used for attendance `medical` status and condonation evidence (Phase 11 link by `document_id`); insurance policies per person with expiry reminders; health camps as events; emergency contacts from profile; audit on every read of a confidential record.
- `counselling_service.py` (`facilities.counselling_appointments`): counsellors publish slots; students/staff book (one active booking per person), reschedule/cancel, no-show tracking; confidential notes encrypted (`notes_encrypted`) visible only to the counsellor; referrals from mentors (Phase 27 `counselling_referrals`) pre-book with the student's consent; anonymised utilisation counts only for IQAC.
- `sports_service.py` (`facilities.sports`): teams (sport, level, coach, members), sports events (internal/inter-college/university/state/national/international; link to `events` for budget/venue), participation records with result/position and evidence; verified participation → `student_achievements` (Phase 27) + activity hours; NAAC 5.3.1 metric (awards) and NIRF counts to Phase 32; selection notifications.
- `wallet_service.py` (`facilities.canteen_wallet`): one wallet per person (`UNIQUE(person_type, person_id)`), top-up via `PaymentGateway` (Phase 12 online flow; `source_type='wallet_topup'`) or counter cash; canteen POS debit by QR (student ID QR) under `FOR UPDATE` with balance check (409 `INSUFFICIENT_BALANCE`), refunds, daily settlement report per canteen vendor, limits (`max_balance`, per-day spend cap for minors with parent setting), parent top-up for wards, statement export; closure on graduation with refund to bank (Phase 12 refund).
